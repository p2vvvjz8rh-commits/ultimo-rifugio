ULTIMO RIFUGIO - PROCEDURA DI SVILUPPO ASSISTITO
===================================================
STATO: configurazione agenti sul ramo sviluppo-agenti, NON una nuova release.

1. Ogni funzionalita' viene sviluppata in un ramo, non direttamente in main.
   Il launcher Windows dell'utente scarica il commit piu' recente di main.
   Per questo una pubblicazione intermedia puo' causare una compilazione
   indesiderata o interrompere una versione stabile.

2. Controlli automatici: le PR contro main attivano il workflow
   .github/workflows/godot-headless.yml che scarica Godot 4.7.2 Linux,
   importa il progetto, avvia la scena per 15 frame e controlla gli errori.
   E' un controllo iniziale, NON equivale a giocare o a esportare Windows.

3. Sul Cloud Codex: controllare che gli script install_script e start_skill
   pubblicati nell'ambiente siano quelli effettivamente attivi. Al momento
   il setup iniziale riportava Godot 4.6.3; in ambiente nuovo allineare
   Godot a 4.7.2 prima delle verifiche definitive. La configurazione Codex
   del sito e separata dai file GitHub: questa procedura non la modifica.

4. Protezione: non modificare manualmente partita.json; non introdurre
   nuove migrazioni senza verificare la compatibilita'. Il progetto
   crea un backup quando si sceglie una nuova partita.

5. I contenuti narrativi sono affidati all'assistente e tenuti volutamente
   fuori dai messaggi di rilascio. Non mettere spoiler nei titoli dei commit,
   nei log di test, nei file README o nei riepiloghi per il giocatore.
   ATTENZIONE: un repository pubblico non e' segreto. Le scene effettivamente
   incluse nel gioco possono essere lette dagli utenti che aprono i sorgenti.

6. Nuova release: dopo il completamento dei test, unire il ramo in main
   soltanto quando si desidera davvero distribuire una nuova versione.
   Descrivere apertamente le meccaniche, mai la trama futura.

7. Indagini aperte:
   - Verificare in Godot il bug di chiusura/salvataggio segnalato su world.gd
     (guardia aggiunta sul ramo di sviluppo per hero gia' liberato).
   - Provare un caricamento/salvataggio reale con un salvataggio temporaneo.
   - Confrontare il rendering e le collisioni con la build Windows.
   - Valutare test piu' completi solo dopo il primo test di import/avvio.

RIASSUNTO PER IL TESTER
La versione disponibile sul desktop rimane Alfa 13 fino al merge in main.
Le modifiche sul ramo sviluppo-agenti non richiedono intervento sul PC.
